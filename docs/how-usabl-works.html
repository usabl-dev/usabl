01

The short answer

usabl proves an accessibility change against the code that made it.

It finds the affected screens, collects machine-checkable accessibility evidence, makes one gate-owned decision, and shows that same result wherever the team works.

It is built for a specific risk. A developer or AI assistant can change interface code, run a scanner, and still call the work done after the scanner skipped a screen or after the code changed again. usabl keeps those gaps visible.

The claim: a verified result means no new deterministic accessibility barrier was found in the affected screens and checks that ran. It does not mean the whole product is accessible. It does not replace testing by disabled people or an accessibility expert.

02

From code to screens

First, usabl decides what must be checked.

Coverage is part of the proof. A check cannot pass a screen it never opened.

  1. Read changed filesStart with local changes or the pull request diff.
  2. Find interface filesMatch the configured user interface file patterns.
  3. Map files to screensUse the route manifest, import graph, broad-impact files, and manual mappings.
  4. Open every affected screenRun the required checks on the full affected set.
  5. Report gapsKeep unmapped files and checks that could not run in the result.

Idle

No configured interface file changed. usabl reports “nothing to check,” returns exit code 0, and issues no verdict.

Not covered

An interface file changed, but usabl could not map or check all required work. The gate returns not_covered and exit code 3.

Coverage rule: usabl checks every affected screen or says what it could not check. It does not sample a few screens and call the accessibility change verified.

03

Inside each screen

Providers collect different accessibility evidence.

A provider is a check that returns evidence drafts. A draft describes what happened to the user, why it matters, and what may fix it. A provider cannot decide the verdict.

axe

Checks rules that can be determined from the rendered page, including names, roles, attributes, and other WCAG-related conditions.

PatternFly rules

Checks interaction behavior that depends on PatternFly components, such as focus entering and returning from a dialog.

Keyboard walk

Moves through interactive controls and records focus order, accessible names, roles, states, and navigation gaps.

Authority rule: deterministic evidence can affect the v0.1.0 gate. Preview and model-based observations may be shown for review, but they cannot create a verified result or receipt.

04

One verdict authority

The gate makes the accessibility decision once.

The gate compares deterministic evidence with the accepted accessibility floor. The floor records existing findings so a team can block new barriers without pretending the old barriers are fixed.

  1. 1. Policy changed? Require human approval.
  2. 2. No interface change? Report Idle.
  3. 3. New barrier? Report regression.
  4. 4. Proof incomplete? Report not covered.
  5. 5. Otherwise Report verified.
Verified, exit 0

No new deterministic accessibility barrier was found in the complete affected coverage.

Regression, exit 1

A deterministic check found a new accessibility barrier compared with the accepted floor.

Not covered, exit 3

Required accessibility coverage or evidence could not be completed.

Approval required, exit 2

Trusted policy, evidence, or gate code changed and must not approve itself.

Errors are not a fifth verdict. An unhandled error returns no verdict, exit code 4, and an explicit “NOT verified” message. Local assistant handling discloses the error instead of presenting it as proof.

05

Trust and receipts

The result stays tied to its evidence.

A verified result can mint a receipt. The receipt lets usabl check whether the proof still matches the current code and policy.

Verified receiptOnly the gate can mint it
Source tree
The exact Git content that was checked.
Base revision
The comparison point when one was used.
Policy hash
The trusted accessibility rules and floor.
Runner version
The installed usabl engine code.
Scanner versions
axe, Playwright, and Chromium versions.
Coverage
The screens checked and any missing coverage.

Local work is tamper-evident

usabl watches its config, route map, evidence floor, waivers, and other guarded paths. A local edit to trusted material becomes approval_required.

Pull requests use a trusted base

CI runs an isolated engine and requires a trusted base reference. The pull request cannot silently rewrite the accepted floor or waivers and then approve itself.

Receipt rule: change the code, policy, or runner and the old receipt no longer proves the new state. Run usabl again.

06

Where the team sees it

Four surfaces project the same gate-owned result.

A surface decides how to present or enforce the result. It does not recalculate accessibility findings or create its own verdict.

SurfaceWhen to use itWhat it doesEnforcement
Command lineWhile developing or debuggingnpx usabl check prints the result and returns its exit code. JSON output is available for automation.Direct exit code
App overlayWhile the Vite app is runningShows the current verdict and findings after a refresh. It hides in automated browser sessions and with ?usabl=off.Advisory only
AI stop hookWhen an assistant tries to finishBlocks a regression, missing coverage, or trusted-policy change. A continuation is allowed once so the assistant does not enter a stop loop.Blocks assistant completion
Pull request and CIBefore mergeRuns against trusted base policy, posts or updates one report, and returns the gate exit code to the check.Repository check

Consistency rule: when two surfaces disagree, that is a product defect. The gate-owned Result object is the source to inspect.

07

Worked example

The modal repair shows the full accessibility proof loop.

The fixture starts with a real focus-management defect on the Clusters screen. A keyboard user opens the dialog, presses Escape, and loses their place.

Before repair
  • The default Clusters modal disables its focus trap.
  • Focus does not enter the dialog reliably.
  • Closing the dialog does not restore focus to “View cluster details.”
  • usabl reports pf-modal-focus-return as a regression.
  • No verified receipt is created.
→
After repair
  • Focus moves into the dialog when it opens.
  • Escape closes the dialog.
  • Focus returns to “View cluster details.”
  • Unit tests and a browser check confirm the behavior.
  • usabl can verify the new source tree and mint a receipt.

Run it: follow the proof-loop guide for setup, exact commands, expected output, the source repair, and final checks.
